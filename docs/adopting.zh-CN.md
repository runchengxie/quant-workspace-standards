# 把规范用到自己的项目

先保留通用原则，再按团队情况选择流程和权限。公开的 AGENTS.md 也包含本工作区的具体做法。在本工作区里，这些规则仍然有效；这页说明方便其他使用者在采用前调整自己的副本。

## 可以沿用的通用原则

修改前了解项目并保留已有工作。独立任务相互隔离，交付前验证实际要交付的版本，只报告真正运行过的检查。凭据和运行数据放在源码仓库外。清理前确认归属、工作已保存、运行资源已满足退役条件。读到一份文档或调用一个 Skill，都不会自动增加权限。

## 本工作区选定的做法

| 事项 | 通用原则 | 本工作区的选择 | 采用前需要决定 |
| --- | --- | --- | --- |
| 合并与审查 | 验证实际合入的版本，遵守仓库保护 | 用户自己创建的 PR，或明确交给 agent 的工作，必要检查通过后可按已有授权合并，无需额外人工审查 | 哪些改动必须有人审查，谁可以合并 |
| 交付授权 | 操作范围以已有用户授权为准 | 默认任务流程包含建分支、推送到用户仓库、创建 PR、合并及清理本任务资源 | 一次任务授权到本地修改、草稿 PR，还是完整交付，要提前写清 |
| 目录布局 | 分开存放源码、私有配置和生成数据，隔离独立任务 | 使用 CODE_ROOT、DATA_ROOT、CONFIG_ROOT，临时 worktree 放在 CODE_ROOT/.worktrees，数据按约定映射 | 根目录、worktree 位置和数据契约如何确定，具体机器路径保持私有 |
| 合入目标 | 核对仓库归属和目标分支当前版本 | 默认使用用户自己的仓库或 fork，目标分支为 main | 实际交付到哪个仓库、哪个分支，是否使用发布分支或合并队列 |

“修复代码”在所有团队里并不都代表允许部署、修改生产数据或写入其他仓库。本工作区的长期交付授权只在它的适用范围内有效。即使无需额外人工审查，仓库保护和必要审批仍须遵守，自动合并权限也不能用来绕过门禁。

## 把决定写在哪里

个人授权偏好放在所有者的全局指令里，共同流程写在工作区指令里，项目边界和实际验证命令写在各仓库的 AGENTS.md。具体路径沿用已有私有配置布局。同一条规则尽量只维护一处，避免多个副本逐渐不一致。

从[中文规范](../AGENTS.zh-CN.md)开始，重点核对[默认开发流程](../AGENTS.zh-CN.md#默认开发流程)和[安全边界](../AGENTS.zh-CN.md#安全边界)。路径设置见[本地配置](workspace-configuration.zh-CN.md)，后续更新可以先用[只读差异检查](maintenance/tools.zh-CN.md#本地规范差异)，保留已有本地增补。
