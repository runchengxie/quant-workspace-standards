# 仓库清理、规则一致性与项目收尾

请检查当前项目及其 submodule 在本轮工作后的状态，清理可以确认的历史残留，核对规则、引用、跨仓契约和交付状态，报告剩余事项。不重新逐函数审计，也不为了表面整洁删除有效历史。

## 归属与状态

记录分支、worktree、已有修改、submodule 固定和实际检出版本、原有问题、质量门禁及未完成迁移。区分已实现、已提交、已合并、已发布、已部署和已被消费者采用，本地代码存在不能证明后续状态。

## 残留与规则

检查失效路径、import、配置、命令、链接、迁移后的旧模块、退役键和参数、artifact、一次性脚本、fixture、依赖、CI、TODO、FIXME、兼容层，以及误入版本控制的缓存、日志和生成文件。删除前核对调用方、动态引用、外部消费者和历史用途。

核对 `AGENTS.md` 和实际存在的开发及 Agent 指引，检查职责、可执行命令、重复和矛盾要求、规则作用域，以及把临时经验固化成长期规则的问题。优先修正原文件中的稳定规则，不擅自改写个人记忆、全局工具配置或仓库外状态。

核对 Git ignore、lint 和 type 例外、coverage exclude 及跳过测试的依据。保留有效设计记录、测试和必要兼容层，不使用排除规则隐藏缺陷。

## 跨仓收尾

检查模块归属、依赖方向，以及生产者和消费者的 API、CLI、schema、配置和 artifact 兼容性。核对固定 submodule SHA 是否支持当前接口。

区分本地已验证变更、provider 尚未被 consumer 采用的变更、下游后续工作和无法验证部分。单仓测试通过不代表整个跨仓系统已经验证。

## 清理边界

只清理确认无效且属于当前任务授权范围的内容。清理 branch 和 worktree 前确认归属、独有提交、未提交及未跟踪文件，核实 PR 已合并并保留可恢复工作。不把审计授权理解为可以合并或删除其他分支。

遵循已有交付授权，不改写历史、不绕过 hook 或分支保护，不在缺少授权时修改生产、数据或全局状态。归属不明或破坏性迁移应报告，不擅自操作。

## 最终验证与报告

检查 diff、Git 状态和 submodule，确认没有意外覆盖用户内容。运行受影响测试、lint、type check 和适用门禁，验证引用及契约。仅根据实际证据记录合并、部署和消费者采用状态。

报告检查范围、残留和规则修正、跨仓版本状态、实际命令及结果、原有失败、新增回归、无法验证部分、剩余风险和后续事项。没有必要清理时直接说明，不为产生修改而删除文件。
## 共同执行约束

修改前读取目标仓库的规则，检查工作区、分支、remote 和 worktree。将 submodule 视为独立仓库，记录路径、gitlink SHA、实际检出 SHA、未提交内容及生产消费契约。不要为了完成检查自动初始化缺失的 submodule 或升级 gitlink，明确报告无法检查的范围。

记录项目实际使用的 lint、type check、test、coverage、security 和 dependency check 基线。根据语言和项目配置选择工具，区分原有失败、新增回归和无法运行的检查。重要结论附代码或配置位置、复现方式或运行证据。

保留用户已有修改。worktree、commit、PR、merge、部署和当前任务清理由会话中已有授权及仓库规则决定，本提示词不额外授予修改其他仓库、用户数据、无关分支或生产环境的权限。破坏兼容性的变更应先说明影响和迁移步骤，仅在实际缺少必要授权时请求确认，不绕过仓库保护。

不得通过删除有效测试、扩大 ignore、降低阈值或隐藏报错制造通过结果。已经确认功能退役的测试可以有依据地删除。只报告实际执行的验证。
